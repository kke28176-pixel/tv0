# AERIX — 自架的影音社群平台

這一版是**真正有後端伺服器 + 資料庫**的版本，不再是打開 `index.html` 就能用的靜態網頁。需要先安裝 Node.js，然後啟動伺服器。

## 一、安裝與啟動

1. 安裝 [Node.js](https://nodejs.org/)（建議 LTS 版本，18 或 20 以上）。
2. 打開終端機 / 命令提示字元，切換到這個資料夹：
   ```
   cd aerix-app
   npm install
   npm start
   ```
   第一次 `npm install` 需要下載套件（含 SQLite 引擎、ffmpeg），要花一點時間，也需要網路連線。
3. 看到「AERIX 網站已啟動」之後，打開瀏覽器輸入：`http://localhost:3000`

伺服器關掉（Ctrl+C）之後資料不會不見，都存在 `data/aerix.sqlite`（資料庫）和 `uploads/`（影片、縮圖、大頭貼、橫幅檔案）裡，下次 `npm start` 就會接著用。

> 如果 `npm install` 在安裝 `better-sqlite3` 時失敗，通常是缺少 C++ 編譯工具。Windows 可以安裝 [Node.js 官方安裝程式時勾選的「Tools for Native Modules」](https://github.com/nodejs/node-gyp#on-windows)，或改用 `npm install --global windows-build-tools`（要用系統管理員權限）。Mac 通常需要先執行 `xcode-select --install`。

## 二、功能總覽

- **資料庫**：SQLite（檔案在 `data/aerix.sqlite`），使用者、頻道、影片、留言、按讚、訂閱都存在裡面，不是瀏覽器暫存。
- **登入**：真正的帳號系統（密碼有加密雜湊），登入狀態存在 Cookie，換分頁、關掉瀏覽器重開、甚至重啟伺服器都還記得（除非你自己登出）。
- **首頁**：沒有任何人上傳影片時會顯示「沒有任何使用者在這裡上傳任何的影片。」，程式裡沒有任何預設影片，不再有分類篩選，只有搜尋。
- **影片管理**（管理頻道 →「影片管理」）：可以修改標題、簡介、公開設定、重新上傳縮圖，也可以刪除影片。
- **自製播放器**：沒有用瀏覽器原生控制列，是自己刻的播放/暫停、進度條、音量、全螢幕。有做基本的防下載措施（見下方說明）。
- **直播**：可以直接用 OBS（或任何支援 RTMP 的直播軟體）推流進來，其他人打開直播間網址就能看，並且有跨使用者共用的即時聊天室。

## 三、怎麼用 OBS 開直播

1. 登入後，點右上角頭像 →「管理頻道」→ 切到「直播」分頁。
2. 打開 OBS →「設定」→「串流」→ 服務選「自訂...」。
3. 把網頁上顯示的「伺服器」貼到 OBS 的「伺服器」欄位（例如 `rtmp://localhost:1935/live`，如果 OBS 跟網站不是同一台電腦，改用頁面上顯示的區網網址）。
4. 把網頁上顯示的「串流金鑰」整串貼到 OBS 的「串流金鑰」欄位。
5. 按 OBS 的「開始串流」，回到網頁的「直播」分頁，幾秒內應該會顯示「直播中」。
6. 想讓直播有標題，先在「直播」分頁的輸入框填好、按「儲存直播標題」，**再**去 OBS 開始串流（標題是開播當下讀取的）。

**串流金鑰不要外流**——知道的人可以冒用你的頻道開播。

直播用的技術是內建一個 RTMP 接收伺服器（監聽 1935 埠），收到影像後用 ffmpeg 轉成 HLS 格式（監聽 8000 埠）給網頁播放，網頁那邊用 hls.js 這個公開的播放器函式庫來播放（需要網路載入，第一次打開直播頁要能連到 `cdn.jsdelivr.net`）。

## 四、關於「禁止下載」，老實說清楚限制

播放器已經做了這些事：
- 沒有用瀏覽器原生的 `<video controls>`，改成自己刻的控制列，所以不會有「另存影片」的按鈕
- 關掉右鍵選單、關掉子母畫面（子母畫面模式底下通常也有另存的入口）

**但這些都只是提高一般使用者隨手下載的門檻，不是真正防下載。** 影片檔案本身還是用一般的網址提供（例如 `/uploads/videos/xxx.mp4`），只要打開瀏覽器開發者工具看網路請求，或是知道網址規則，還是抓得到檔案。如果之後真的需要「很難被下載」的等級，通常要做到：
- 影片切成一段一段加密的串流（像直播用的 HLS，VOD 也可以做），金鑰跟播放權綁在一起動態發放
- 或是走真正的 DRM（例如 Widevine / FairPlay），這牽涉到額外的授權服務，不是單純自己寫程式能達到的

這部分如果之後想要做得更完整，我可以再幫你規劃。

## 五、目錄結構

```
aerix-app/
  server/          後端程式（Express + SQLite + 直播）
  public/          前端網頁（HTML/CSS/JS，透過 API 跟後端溝通）
  uploads/         使用者上傳的影片、縮圖、大頭貼、橫幅（執行時期產生）
  media/           直播轉出的 HLS 檔案（執行時期產生，可以刪掉重新直播就會重建）
  data/            SQLite 資料庫檔案 + 登入用的金鑰檔（執行時期產生）
```

## 六、還沒做 / 可以之後再加強的部分

- 這是單機示範用的設定（例如 `express-session` 換成了 JWT Cookie、沒有做 HTTPS），如果要真的公開到網路上給不特定的人使用，要另外處理 HTTPS、更嚴謹的檔案大小/類型檢查、防止濫用上傳等等
- 觀看人數是模擬的假數字，不是真的統計
- 沒有做通知、播放清單、彈幕、分眾推薦這些進階功能

## 七、部署到網路上（重要）

**GitHub Pages / Netlify / Vercel 靜態託管都不能用**——它們只能放靜態網頁，不能執行 Node.js，所以註冊、登入、上傳都會失敗。這個專案必須部署在「可以執行 Node.js 的主機」：

- **Render.com**（最簡單）：註冊後選 New → Blueprint，連接你的 GitHub 儲存庫，會自動讀取 `render.yaml` 部署。要有「永久磁碟」（付費）才能保存帳號、影片；免費方案每次重啟資料都會消失。
- **Railway / Fly.io / 自己的 VPS**：同樣執行 `npm install && npm start`，並設定環境變數 `DATA_DIR` 與 `UPLOAD_DIR` 指向永久磁碟。

**OBS 直播的限制**：直播需要對外開放 TCP 1935（RTMP）與 8000 兩個連接埠，Render 這類只開放網頁埠的平台做不到。要直播請用自己的 VPS（開放這兩個埠），或 Fly.io / Railway 的 TCP 轉發功能。另外網站若是 https，直播播放網址也需要 https（需要在 VPS 前面加反向代理），這部分比較進階。
